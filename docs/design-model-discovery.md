# 全量模型数据实现

行为约束见 [功能规格](SPEC-model-discovery.md)。项目架构术语见 [术语表](glossary.md)。

## 数据链路

1. `core/codex_radar_client.py`（网站读取模块）使用标准库同时读取 `/api/intelligence-efficiency-metrics`（软件工程数据接口）及 `/api/visual-spatial-reasoning`（视觉空间数据接口），检查网站的缓存状态标记和响应结构。
2. `core/intelligence.py`（成绩整理模块）将 `points`（成绩列表）整理为按模型与档位唯一的记录；保留源更新时间、分数、有效题量及平均分钟数，校验有限数值。软件工程兼容当前第 3 版及第 2 版的有效题量字段；视觉空间使用其有效题量字段。
3. 按模型与档位取两个分项的并集，综合分采用 `(工程分×工程题量 + 视觉分×视觉题量) / 总题量`，与网站当前前端算法一致。仅两侧都有效时计算；平均耗时也要求两侧都有数值。
4. `core/iq_table.py`（推送排版模块）按中文显示宽度动态排列完整模型名称，以无语言标签的代码块输出全量成绩与源时间。现有旧结构排版函数保留通用名称兼容性，不用于实时抓取。
5. 定时表格入口直接读取并格式化统一成绩；即时查询及变化提醒向解析器传入相同成绩。解析器提供完整文本与排除整体时间的稳定变化依据；展示层不再从智商文本中猜测模型名称。
   Hermes 定时脚本目录使用 `scripts/hermes_cron_codex_radar_iq_table.py`（定时表格启动入口）的内容，安装名保持为既有的 `codex_radar_iq_table.py`。它优先使用部署目录环境配置，否则从自身位置定位相邻的项目目录，并执行项目内的真实入口。
6. 变化提醒在冷却期保留待提醒的旧比较基线，下一次允许提醒时能够报告期间新增模型。

运行副本核对：变化提醒采用 30 分钟冷却且首次输出全部分区；此行为在源仓库中维护。表格查询的运行修补由统一成绩读取取代其动态脚本加载实现，投递仍交由 Hermes 的既有任务负责。

## 运行与验证

- 不新增第三方运行依赖，不在代码中放置设备、账户或投递目标。
- 测试数据采用合成最小样本；实时验收使用临时目录中的公共数据，不提交整站抓取或运行状态。
- 发布顺序：先提交并同步设计，再添加测试、实现和源仓库提交，随后备份并同步既有 Hermes 应用文件。任务定义保持原样，使用既有任务做一次受控运行及状态核验。
- 网络或格式异常不能用旧数据掩盖；错误信息包含数据类别，不包含认证信息或投递目标。

公共来源核对日期：2026-09-08。网站源码使用上述两个接口，综合算法按有效题量加权。入口：[Codex 雷达](https://codex-reset-radar.pages.dev/)。
