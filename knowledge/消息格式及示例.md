# 消息格式及示例

## 推荐格式

飞书聊天消息不稳定渲染 Markdown 表格。模型数据使用无语言标签的代码块，以等宽字体显示三列：

````markdown
降智雷达：14:45

```
模型                 分数  耗时
Sol max             107.6  35分钟
Sol xhigh            92.8  28分钟
Terra max           102.2  34分钟
GPT-5.5 high         79.4  16分钟
```
````

呈现规则：

- 标题在代码块外，保留正常字号。
- 代码块不写语言名称，避免顶部出现多余标签。
- 模型列左对齐，分数列右对齐，耗时列左对齐。
- 中文按双宽字符计算，确保中英文混排时表头和内容对齐。
- 数据为空时任务应明确失败，不能发送“暂无数据”冒充正常结果。

## 不采用 Markdown 表格

以下语法在飞书聊天里可能原样显示竖线：

```markdown
| 模型 | 分数 | 耗时 |
|---|---:|---:|
| Sol max | 107.6 | 35分钟 |
```

Markdown 表格适合飞书文档或支持表格扩展的编辑器，不适合作为本项目聊天推送格式。

## 消息卡片边界

飞书消息卡片适合颜色、分栏、按钮和跳转等复杂交互，但需要使用卡片消息接口。普通文本投递链路不会自动把 Markdown 表格转换成卡片。

本项目默认使用等宽代码块；只有明确需要交互组件时才升级为消息卡片，并为卡片发送建立独立测试和失败回退。

## 自动验证

格式测试至少覆盖：

1. 输出包含起止代码块标记。
2. 起始标记后不附加语言名称。
3. 模型、分数、耗时列按显示宽度对齐。
4. 当前数据中的全部模型均被输出。
5. 空数据抛出错误。
