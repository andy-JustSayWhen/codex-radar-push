# 消息渠道的选择

## 目标

定时雷达消息需要稳定送达、结构清晰、错误可观测，并且不能把会话编号或访问凭据写进代码仓库。

## 选择维度

| 维度 | 微信机器人通道 | 飞书机器人通道 |
|---|---|---|
| 定时推送稳定性 | 可能受到账号级发送限制和短时冷却影响 | 已配置应用的会话通常可以稳定投递 |
| 失败证据 | 检查任务的投递错误和网关日志 | 检查任务的投递错误、飞书连接状态和任务产物 |
| 结构化展示 | 以普通文本为主 | 支持富文本和代码块；复杂卡片需要使用飞书卡片接口 |
| 表格兼容性 | 不应依赖 Markdown 表格渲染 | 聊天消息不会稳定渲染 Markdown 表格 |
| 配置方式 | 运行时提供目标会话 | 运行时提供目标会话 |

## 本项目选择

定时降智雷达使用飞书作为发送渠道。理由：

1. 定时任务和发送结果可以分别验证。
2. 等宽代码块能稳定呈现模型、分数和耗时。
3. 发送目标通过环境变量注入，不进入仓库。

安装任务前设置：

```bash
export CODEX_RADAR_DELIVERY_TARGET='feishu:<chat_id>'
```

`<chat_id>` 是运行环境中的会话编号，不能提交到代码仓库。

## 验证闭环

1. 确认任务处于启用状态，计划时间符合预期。
2. 临时执行一次任务。
3. 检查任务产物包含完整内容。
4. 检查运行状态为成功。
5. 检查任务错误和投递错误均为空。
6. 在目标客户端确认消息实际到达且格式正确。

“脚本运行成功”只证明内容生成完成；“投递错误为空”只证明发送端未报告失败。两者与客户端可见结果必须一起验收。

## 隐私边界

- 会话编号、用户编号、机器人密钥、访问令牌、设备地址和账号名不得写入源码、测试、示例或提交历史。
- 示例一律使用 `<chat_id>`、`<host>` 等占位符。
- 发布公开仓库前，同时扫描当前文件和全部提交历史。
